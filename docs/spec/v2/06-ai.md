# 06 — AI

## LLM gateway

All model calls go through one internal interface in the API:

- **Providers** are adapters (Claude first; others can be added). Business code never imports a
  provider SDK directly.
- **Routing** by task: a fast/cheap model for classification, short answers and simple tool calls;
  a strong model for multi-step analysis and planning. Configurable per agent and, later, per tenant.
- **Metering:** every call records tokens and cost → `usage_events` (`ai_credits`).
- **Limits:** per-tenant credit balance checked before a call.

## Tools

Agents act only through tools: typed backend functions with a JSON schema.

| Kind | Examples | Execution |
|---|---|---|
| Read | `find_client`, `list_sessions`, `get_metric(name, period, filters)` | Immediate, permission-checked |
| Low-risk write | `create_booking`, `add_lead_note` | Immediate or pending, per tenant setting |
| Sensitive write | `refund_payment`, `cancel_entitlement`, `change_price`, `send_campaign`, `change_permissions`, `delete_client` | Always a Pending Action |

Every tool call checks: authenticated user → tenant → permission → input validation → risk policy.
The tool runs **with the requesting user's permissions** — the agent can never do more than the user.

## Pending actions

1. Agent calls a sensitive tool → server stores a `pending_action` (payload + hash, expiry) and
   returns a human-readable preview.
2. UI shows the preview with Confirm / Reject.
3. Confirm sends the `pending_action_id` (not "yes" to the model).
4. Server re-validates (permission, current state, hash, expiry) and executes exactly once.
5. Result and actor chain (user → agent → tool) written to `audit_log`.

## Metrics layer

The analyst agent queries named, defined metrics (revenue, active clients, churn, occupancy,
no-show rate, lead conversion, ...) via `get_metric`, never free-form SQL. Metric definitions live
in code and are shared with dashboards, so AI answers match the numbers on screen.

## Safety

- Client-entered text (notes, names, messages) is treated as data, never instructions; it is
  delimited in prompts and tools never execute on its say-so.
- Data minimization: tools return only fields needed for the task.
- Hebrew and English prompts and evaluations; a small eval set of business questions per vertical,
  run in CI when prompts or models change.

## Agents (later phases)

Manager, Finance, Marketing, Booking, CRM, Analyst — each = instructions + tool subset + permissions.
They share the gateway and tool layer; the Manager routes questions to specialists.
