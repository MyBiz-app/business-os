## מה אני צריך ממך (פעולות, מתי שנוח)

1. ✅ **תבניות המייל ב-Supabase**: מוגדרות (נבדק ב-10.10, זהות ל-`supabase/templates/`).
2. ✅ **כתובות החזרה ב-Supabase**: מוגדרות (Site URL ו-`https://business-os-alpha-drab.vercel.app/**`).
3. ✅ **האפליקציות בטלפון (Expo, בחינם)**: פורסמו (10.10) ופתוחות בדפדפן: `mybiz-client-app.vercel.app`, `mybiz-business-app.vercel.app`, `mybiz-staff-app.vercel.app`. אפשר להוסיף למסך הבית. עדכון אחרי שינוי: Actions ← Deploy the Expo apps to the web ← Run workflow.
4. **התחברות עם Google** (כ-10 דקות):
   1. ב-[Google Cloud Console → Credentials](https://console.cloud.google.com/apis/credentials) יוצרים OAuth client מסוג Web application.
   2. ב-Authorized redirect URIs מדביקים את ה-Callback URL שמופיע ב-[Supabase → Authentication → Sign In / Providers → Google](https://supabase.com/dashboard/project/_/auth/providers). הכתובת נראית כך: `https://<project>.supabase.co/auth/v1/callback`.
   3. מעתיקים את ה-Client ID וה-Client Secret ל-Supabase ומפעילים את Google. הכפתור יופיע באתר לבד, תוך 5 דקות לכל היותר.
4. **התחברות עם Apple** (אופציונלי, אפשר בהמשך). הכפתור כבר באתר, מושבת עם תווית "בקרוב", ויופעל רק אחרי השלבים האלה. צריך חשבון [Apple Developer](https://developer.apple.com/programs/) בתשלום שנתי:
   1. ב-Apple Developer → Identifiers יוצרים App ID (עם Sign in with Apple) ו-Services ID (זה ה-Client ID).
   2. ב-Services ID מגדירים את הדומיין ואת ה-Return URL: ה-Callback של [Supabase → Authentication → Sign In / Providers → Apple](https://supabase.com/dashboard/project/_/auth/providers).
   3. יוצרים Key עם Sign in with Apple ומורידים את קובץ ה-`.p8` (אפשר להוריד פעם אחת בלבד).
   4. ב-Supabase מדביקים את ה-Services ID וה-Secret Key (JWT שנוצר מה-`.p8`, [המדריך של Supabase](https://supabase.com/docs/guides/auth/social-login/auth-apple); הוא פג כל 6 חודשים, צריך לחדש) ומפעילים את Apple.
   5. ב-Vercel מגדירים משתנה סביבה `AUTH_APPLE_ENABLED=true` ועושים deploy. הכפתור יהפוך לפעיל. את ה-`.p8` לא שולחים לי.
5. **להחליף את הסיסמאות הזמניות** של חשבונות הדמו. **לא לשלוח לי** את הסיסמה החדשה.
6. **החלטות פתוחות:** [#46](https://github.com/MyBiz-app/business-os/issues/46) ספק סליקה (ממנו יגיעו גם Apple Pay ו-Google Pay), [#47](https://github.com/MyBiz-app/business-os/issues/47) ספק חשבוניות, [#36](https://github.com/MyBiz-app/business-os/issues/36) שם המותג. הספקים יחוברו כשהעסק יתחיל לפעול (X21), והשם הוא MyBiz בינתיים.
7. **דוח התיקונים והשיפורים** שלך, לפני העלייה לאוויר.
8. **להדליק אחסון קבצים (2 דקות, מתי שנוח לפני העלייה לאוויר).** ב-[Supabase → Project Settings → API Keys](https://supabase.com/dashboard/project/mywfwzdrlbpxeheszasd/settings/api-keys) מעתיקים את ה-secret key, וב-Render (שירות ה-API ← Environment) מוסיפים `API_STORAGE_PROVIDER` = `supabase` ו-`API_STORAGE_SETTINGS` = `{"url": "https://mywfwzdrlbpxeheszasd.supabase.co", "service_key": "<המפתח הסודי>"}`. **לא לשלוח לי** את המפתח.
9. **להדליק ניטור שגיאות (10 דקות, לפני העלייה לאוויר).** פותחים חשבון [Sentry](https://sentry.io) חינמי ושלושה פרויקטים (Python, Next.js, React Native) ומגדירים את שלושת ה-DSN לפי `docs/monitoring.md`. אפשר להוסיף גם ניטור זמינות חיצוני חינמי על `/health/ready`.

## בעבודה

- כניסה, מסך פתיחה ו-Face ID באפליקציה (סבב 3, פרוסה R7): מסך כניסה ממותג עם רקע נע, כרטיס זכוכית ושש תיבות לקוד (הדבקה ושליחה אוטומטית); מסכי פתיחה ונעילה עם לוגו בעומק; הצעה חד-פעמית "להיכנס עם Face ID / טביעת אצבע?" אחרי הכניסה הראשונה; בחירת זמן נעילה (מיד / 30 שניות / 5 דקות); מצבים ריקים מאוירים.
- אפליקציה אחת לכל התפקידים (סבב 3, פרוסה R4): אפליקציית MyBiz (`apps/client-app`) בונה עכשיו את האזורים של האדם (צוות MyBiz, עסקים שבהם הוא עובד, עסקים שבהם הוא לקוח), פותחת את האחרון שהיה בשימוש, ובפרופיל יש רשימת "החלפת אזור". מסכי הלקוח נמצאים ב-`(client)`; אזור העסק ואזור צוות MyBiz הם מסכי המתנה עד שהמסכים שלהם יעברו (R5, R6). `business-app` ו-`staff-app` ממשיכות לעבוד עד אז.
- אפליקציה אחת, אזור העסק (סבב 3, פרוסה R5): מסכי העסק (היום, לקוחות, תיבה, מספרים, אני, וגם לקוח, ליד, הצעת מחיר, שיעור, עבודות, הזמנת מגרש, זמינות ולוח משמרות) עברו לאזור העסק באפליקציית MyBiz, והלשוניות לפי הרשאות. `business-app` ממשיכה לעבוד עד ההסרה (R13); אזור צוות MyBiz עדיין מסך המתנה (R6).

## הושלם (עבודה אחרונה)
- **ליטוש טבלאות ותפריט נייד ב-CRM.** כל טבלאות הנתונים באפליקציית העסק ובקונסולה באותו מראה (שורת כותרת שקטה, קווים בין שורות, ריחוף עדין); מפת החום ולוח המשמרות פטורים. בטלפון יש קו מפריד בין התפריט לבר הכחול.
- **אפליקציה אחת בלבד (R13).** אפליקציות Expo הישנות של העסק ושל צוות MyBiz (`apps/business-app`, `apps/staff-app`) הוסרו: המסכים שלהן נמצאים ב-`apps/client-app`. CI, תהליכי הפריסה לווב ועדכוני EAS, מזהי החנויות והמסמכים מתייחסים עכשיו לאפליקציה האחת. הכתובות הישנות `mybiz-business-app` ו-`mybiz-staff-app` רק מפנות ל-`mybiz-client-app` (מריצים את *Deploy the Expo app to the web* עם *legacy-redirects*); פרויקטי Vercel ו-EAS לא נמחקו. שני סקריפטי ה-e2e של הטלפון הוסרו איתן; הבדיקה הסופית (R14) מכסה את אזורי העסק והצוות באפליקציה האחת.
- **מסך הבית של הלקוח לפי תחום (סבב 3, פרוסה R11).** הבית באפליקציית הלקוח הוא עכשיו רשימת כרטיסים שהתחום קובע (`client_home` בקטלוג, תתי-קטגוריות יורשות): ההזמנה הבאה עם ניווט, הוספה ליומן וביטול; מנוי או כניסות שנשארו; קיצורי הזמנה לשיעורים, תורים והשכרה; להזמין שוב; חיות או ילדים; הצהרת בריאות; מסמכים, הצעות וכתובות; עדכונים אחרונים; כתובות הסניפים. "ההזמנות שלי" מציג הזמנות קרובות ככרטיסים עם אותן פעולות, העדכונים מקובצים (היום, השבוע, קודם) עם אייקונים, וקביעת תור היא מסלול ממוספר עם סיכום וכפתור הוספה ליומן. ב-API: `home_cards` ב-`/client/businesses` ו-`GET /client/locations`. לא בפרוסה הזו: הרשמה לשיעורים (R9), השכרת מגרשים (R10), פרופיל (R8); שעות הפעילות של העסק דורשות הרשאת קריאה ללקוח.
- **סצנת פתיחה בתלת-ממד בדף הבית ומסך טעינה תלת-ממדי.** סצנה מעל הכותרת הראשית (יומן, לקוחות, תשלומים, הודעות, צוות ודוחות עפים פנימה ומתחברים סביב הלוגו; העכבר מטה אותה קלות) ומסך טעינה שבו הלוגו מתהפך כאריח תלת-ממדי בתוך טבעות מסתובבות. בלי ספרייה; בתנועה מופחתת מוצג המצב הסופי.
- **מסגרת כחולה אחידה ל-CRM ולקונסולה.** הבר העליון תואם עכשיו לתפריט הצד (Navy אחד, טוקן `--frame`) בבהיר ובכהה; הרקע מאחורי הכרטיסים באפור-כחלחל עדין בבהיר. צבע הסניף ממשיך לצבוע כפתורים ואת הפריט הפעיל בתפריט.
- **הצעות זמנים להשכרת מגרשים (API).** נקודת קצה חדשה עונה על "מתי נוח לך?": המגרשים הפנויים בדיוק בשעה המבוקשת, ועד 5 הצעות קרובות אחרות (מגרש אחד לכל שעת התחלה, באותו יום, ביום שלפני ובשני הימים שאחרי), עם הפרש הדקות מהשעה שביקשת. לקוח אחד למשבצת נשאר נאכף בהזמנה. מסך האפליקציה יגיע בחלק ההשכרה של סבב 3.
- אנימציות עדינות באתר וב-CRM: קטעי האתר נכנסים בעדינות בגלילה, כרטיסי התכונות בדף הבית מציגים חזותיות קטנות בלולאה, ורשימות ריקות ב-CRM מציגות איור מונפש קטן. הכול נעצר למי שמעדיף פחות תנועה.
- **API סבב 3: מאמן, פרסום שבועי וסטטוס.** שיעור מציג עכשיו את המאמן שלו (שם ותמונה, בלי אימייל) ואפשר לסנן לפי מאמן; עסק מציג שיעורים כמה ימים קדימה (ברירת מחדל 7) או פותח את השבוע הבא בכל שבוע ביום ובשעה שקבע, והצוות יכול לפרסם את השבוע הבא מוקדם יותר; הלקוח רואה מתי השבוע הבא נפתח. אפשר להגדיר בפרופיל סטטוס קצר (עד 80 תווים). מיגרציה 0080; שמונה ההחלטות של סבב 3 רשומות ביומן ההחלטות (X42-X49).
- **ניהול יומן (R12, סבב 3).** בלוח השיעורים יש כפתור "פרסום השבוע הבא", בהגדרות קובעים איך שיעורים נפתחים (כמה ימים קדימה או יום ושעה לפרסום שבועי), ובאפליקציית העסק אפשר לבטל או לשחזר שיעור שלם (הנרשמים מקבלים הודעה). צ'ק-אין והוספת לקוח לשיעור כבר היו במסך השיעור.
- **האפליקציות ב-Expo ובאתר מסונכרנות.** שלוש אפליקציות ה-Expo פורסמו מחדש (EAS Update, ענף `preview`) עם כתובות ה-API וה-Supabase של סביבת הבדיקה בתוך החבילה, מה שתיקן את השגיאה "משהו השתבש בשליחת הקוד (0)" בהתחברות; הקישורים של פרויקט EAS (כתובת העדכון, גרסת ריצה, מזהי חבילה) נשמרו עכשיו ב-`app.json` של כל אפליקציה. גרסאות הווב של האפליקציות, אתר השיווק וה-CRM נפרסו מחדש מאותה גרסה. פרסום ממחשב דורש `--environment preview` ואת שלושת ערכי `EXPO_PUBLIC_*`; תהליך "Publish Expo app updates (EAS Update)" ב-GitHub עושה את אותו הדבר.
- **ה-CRM בטלפון, מסודר.** כפתורי הכותרת (יומן, צוות) בנויים כרשת אחידה, בורר יום/שבוע/חודש ביומן בשורה משלו, שדות תאריך ושעה קומפקטיים במקום רחבים, והחלון "עובדים במשמרת" נפתח ליד המקום שנלחץ ונשאר כולו על המסך.
- **לוגו וצבע לכל סניף.** לכל סניף אפשר להגדיר לוגו וצבע משלו (בעמוד הסניף, למי שמנהל הגדרות); סניף שלא הגדיר מציג את אלה של הרשת. התפריט הצדדי מציג את הלוגו והצבע של הסניף הנבחר, ובסניפים עם לוגו משלהם הוא מופיע גם ברשימת הסניפים. API: העלאה ומחיקה של לוגו לסניף, צבע לסניף, ומיגרציה 0079. עוד לא באפליקציות Expo.
- אפליקציות: נעילה עם Face ID / טביעת אצבע. בכרטיס ההעדפות בשלוש האפליקציות יש מתג שנועל את האפליקציה בהפעלה ואחרי 30 שניות ברקע. Face ID באייפון דורש בנייה ייעודית (לא Expo Go). Passkey לא נבנה כי Supabase עדיין לא תומך בו.
- קודים של 6 ספרות וכניסה עם קוד: כל קוד שמגיע במייל (כניסה, אימות הרשמה, איפוס סיסמה) הוא עכשיו בן 6 ספרות במקום 8. חדש: באתר יש "כניסה עם קוד חד־פעמי", ובמסך הכניסה של שלוש האפליקציות בוחרים אם לקבל את הקוד במייל, ב-SMS או בוואטסאפ. המייל עובד כבר עכשיו. SMS ווואטסאפ בנויים (מאמתים את המספר פעם אחת בעמוד החשבון) ונשארים מוסתרים עד שמפעילים ספק בהשקה, כי הוא עולה כסף לכל הודעה.
- **לידים: בחירת עמודות להצגה.** תפריט "שלבים" עם תיבות סימון בלוח הלידים מציג רק את עמודות התהליך שנבחרו (חדש, נוצר קשר, ניסיון, הצעה, נסגר, אבד); עובד בטלפון, בעברית ובמצב כהה.
- **מסך פתיחה.** האתר, ה-CRM ושלוש האפליקציות נפתחים עם לוגו MyBiz מונפש קצר (קופץ פנימה, "נושם" ונעלם בעוד כשנייה וחצי) מעל הדף. הוא לא חוסם את הטעינה, באתר מופיע פעם אחת לכל סשן דפדפן, מתאים לבהיר/כהה, ובהפחתת תנועה מציג דהייה פשוטה וקצרה.
- אפליקציות בסגנון סבב 2: שלוש אפליקציות Expo עברו לפונט Assistant (כותרות אנגליות מודגשות ב-Plus Jakarta Sans כמו באתר), הודעות שמירה קופצות בתחתית המסך (הצעות מחיר, פניות, ניסיון עסק, פרופיל), כפתור שמש/ירח להחלפת מצב כהה/בהיר במסך הכניסה וליד בחירת המראה בכרטיס הפרופיל, ושדות אימייל, טלפון וקוד משמאל לימין; טלפונים ואימיילים בתוך משפט בעברית מבודדים ולא "קופצים" בתוך השורה.
- **כפתור נגישות: גרירה וסגירה.** אפשר לגרור את כפתור הנגישות הצף באתר ובמסכי ההתחברות לכל מקום (עכבר, מגע או חצים), הוא נשאר בתוך המסך וזוכר מיקום; איקס שחור קטן מסתיר אותו וקישור בפוטר מחזיר אותו.
- **מיילים מעוצבים.** כל המיילים חולקים עכשיו עיצוב אחד של MyBiz (כותרת כחולה כהה עם הלוגו, קוד גדול וברור, כפתור, מצב כהה, עברית מימין לשמאל ואנגלית): קוד כניסה, אימות הרשמה, איפוס סיסמה, הזמנה, שינוי כתובת, אישור זהות והתראות אבטחה (Supabase, עברית + אנגלית באותו מייל), וגם התראות ללקוחות, מיילי משמרות לצוות ומייל הפתיחה. הוראות הדבקה: `docs/deploy/auth-settings.md`.
- **הודעות שמירה ושגיאה ברורות.** הודעות "נשמר" ושגיאה מופיעות עכשיו כהודעה צפה צמודה לתחתית המסך (הצלחה 5 שניות, שגיאה 9, כפתור סגירה, נעצרת בריחוף, מעל חלונות, מצב בהיר/כהה, RTL, כיבוד הפחתת תנועה), במקום שורה בראש הטופס שנעלמה מהעין אחרי גלילה. כל הטפסים מקבלים זאת דרך `FormNotice` / `FormError`; שגיאות נשארות גם בתוך הטופס.
- **אפליקציות: העדפות נגישות.** בכרטיס ההעדפות בשלוש האפליקציות יש עכשיו גודל טקסט (רגיל / גדול / גדול מאוד), מתג להפחתת תנועה וניגודיות גבוהה. טקסט אנגלי מודגש ב-Plus Jakarta Sans כמו באתר, ועברית נשארת ב-Heebo.

- **מראה ה-CRM, חלק 1.** כל האפליקציה משתמשת עכשיו כברירת מחדל בפלטת האתר (כחול ראשי, רקע Cloud White, מצב לילה כחול כהה) ובגופן Plus Jakarta Sans לטקסט לטיני. מסכי כניסה, הרשמה, בדיקת מייל וסיסמה בפריסה מפוצלת עם פאנל מותג כהה וכפתור נגישות. עמודת הניווט בכחול כהה (בהיר וכהה). נבדק בסריקה ובבדיקות נגישות בעברית/בהיר ואנגלית/כהה. הבא: ליטוש מסכים בודדים לפי הצורך.
- **עיצוב מחדש של דף הבית השיווקי.** Hero כהה, רשת יכולות, אזור AI כהה, מחירים חיים, אודות ופוטר כהה, בפלטה החדשה (Midnight Navy, Primary Blue, AI Purple, Electric Cyan, Cloud White). האתר השיווקי תמיד בהיר (`.mk` ב-`globals.css`). קישורי הרשתות החברתיות בפוטר מצביעים בינתיים על כתובות זמניות (למשל facebook.com/mybiz), ואפשר להחליף אותן במשתני `NEXT_PUBLIC_SOCIAL_*`. בדפים הציבוריים יש כפתור נגישות (שפה, יום/לילה, ניגודיות, גודל טקסט, הפחתת תנועה, הצהרה) והדגמת מוצר מתחלפת שאפשר לעצור. הדף הקודם שמור בענף `backup/landing-v1`.
- **דפי האתר הפנימיים באותו סגנון.** תכונות, תחומים, מחירים, אודות, יצירת קשר ומדריך ההתחלה נפתחים עכשיו בבאנד כחול כהה משותף (`PageHero`).
- **כותרות באפליקציה העסקית.** כותרות המסכים באפליקציה העסקית ובקונסולה כבדות וצפופות כמו באתר השיווקי, ובאשף ההרשמה אין יותר מסגרת פוקוס סביב כותרת כל שלב. עברתי על כל מסכי האפליקציה העסקית ועל אשף ההרשמה עם נתוני דמו: הפלטה, התפריט והכרטיסים כבר אחידים.
- **מוכנות ל-production בקוד (פרוסה 7 בדרך לעלייה).** הכול נבנה ונשאר כבוי: `render.production.yaml` (Blueprint אחד שיוצר את ה-cron היומי והשעתי כשמאשרים production), ספירת מגבלות קצב ב-Redis כשמגדירים `API_RATE_LIMIT_REDIS_URL` (אם Redis נופל סופרים מקומית), וה-API מסרב לעלות ב-production כשחסרה הגדרה חובה או שהיא עדיין מצביעה ל-localhost. [רשימת הבדיקה לעלייה](deploy/go-live-checklist.md) מפרטת כל חסם, איך מדליקים אותו ואת ההגדרות הנדרשות. שום דבר שעולה כסף לא דלוק.
- **אתר: עמודים קלים יותר.** השרת קורא רק את קובץ השפה של המבקר, וכל חלק באתר (שיווק, כניסה, אפליקציית העסק, קונסולת MyBiz) שולח לדפדפן רק את קבוצות ההודעות שהמסכים שלו משתמשים בהן. מסכים שמתרעננים לבד מפסיקים אחרי 5 דקות חוסר פעילות, מדלגים על לשונית מוסתרת או לא מחוברת, ולא מתרעננים פעמיים בתוך 15 שניות.
- **ניטור שגיאות ובדיקת זמינות (B3).** Sentry מחובר ל-API, לאתר ולשלוש אפליקציות הנייד, וכבוי עד שמגדירים DSN (`API_SENTRY_DSN`, `NEXT_PUBLIC_SENTRY_DSN`, `EXPO_PUBLIC_SENTRY_DSN`). גופי בקשות, עוגיות, כותרות, פרמטרים בכתובת ופרטי משתמש מוסרים לפני שליחה, וכל שגיאת API נושאת את מזהה הבקשה ומזהה העסק שמופיעים גם בלוגים. תהליך הבדיקה המתוזמן בודק עכשיו את `/health/ready` ואת האתר עם ניסיונות חוזרים, ונכשל (ו-GitHub שולח לך מייל) כשאחד מהם למטה. הוראות: `docs/monitoring.md`.

- **משמרות: סידור הוא טיוטה עד שמפרסמים אותו.** מנהלים מתכננים משמרות כטיוטה (מסגרת מקווקוות ותווית "טיוטה"); הצוות והתצוגה בטלפון רואים רק משמרות שפורסמו. פס מעל הלוח סופר את הטיוטות ומציע "פרסם עכשיו". הבעלים קובע את הקצב בפאנל "פרסום הסידור" (יומי / שבועי / חודשי, יום בשבוע או בחודש, שעה; ברירת מחדל כל יום ראשון ב-08:00, או ידני בלבד). משימה שעתית (`publish-shifts`, workflow חדש `jobs-hourly-staging.yml`) מפרסמת מה שהגיע זמנו. מיגרציה 0067; משמרות קיימות נחשבות מפורסמות. העובדים מקבלים מייל עם המשמרות החדשות שלהם אחרי פרסום הסידור (ידני או מתוזמן): מייל אחד לכל אדם, משימת `notify-shifts` ב-`emails-staging.yml`, וכיבוי/הפעלה בהגדרות אישיות ← התראות במייל (מיגרציה 0068). נשלח רק כש-`EMAIL_PROVIDER` מוגדר (אחרת רק רישום ביומן), בלי שירות בתשלום. **התראת פוש קודם, מייל כגיבוי:** משימות ההתראות (משמרות שפורסמו, משמרות ששונו, התראות ללקוחות) שולחות עכשיו פוש לטלפון הרשום של האדם דרך Expo, ורק אם אין טלפון רשום או שהפוש לא נמסר נשלח מייל (`app/messaging/push.py`, `API_PUSH_PROVIDER`, בלי מיגרציה). **שינויים בסידור שכבר פורסם** (משמרת שהוזזה, נערכה, הועברה לאדם אחר או הוסרה אחרי שהעובד קיבל מייל) נשלחים גם הם: טריגר במסד הנתונים רושם את השינוי (`shift_changes`, מיגרציה 0069), ואותה משימה שולחת מייל אחד לאדם אחרי 15 דקות של שקט (לכל היותר שעתיים), עם המצב ההתחלתי והסופי בלבד; שינוי שבוטל לא נשלח. אותה אפשרות כיבוי, וגם באפליקציית העסק (לשונית אני).

- **משמרות: שיבוץ לפי חדרים ועמדות.** כל סניף מגדיר חדרים משלו ("פילאטיס 1", "יוגה 2", "מטבח") תחת *חדרים ועמדות* בלוח המשמרות; משמרת בוחרת חדר, כמה אנשים יכולים לחלוק חדר באותה שעה, והסידור לפי סניפים מקבץ כל יום לפי חדר. בדמו של Pulse Fitness, Urban Slice ו-Studio Bloom כבר יש חדרים. הבא: סידור טיוטה מול מפורסם עם קצב פרסום (תהליך נפרד).
- **משמרות: קטעי חוסר איוש מסומנים בכל מקום.** בכרטיסי היום בטלפון מופיע כל קטע שבו בסניף יש פחות אנשים מהנדרש בכללי הכיסוי, ובטבלת הזמן של הסניפים הקטעים האלה מוצללים בעמודת הסניף.
- **אפליקציית הלקוח: שגיאת טעינה כבר לא נראית כחשבון ריק.** בבית, בהזמנות, בקבלות, בהצעות, במסמכים, בכתובות ובבני המשפחה מוצג כרטיס "לא הצלחנו לטעון" עם כפתור "נסו שוב" כשהבקשה נכשלת. רשימות ריקות בבית, בהזמנות ובעדכונים משתמשות עכשיו בכרטיס אחיד, ובזמן טעינה מוצג מחוון טעינה.
- **יצירה ואירועים: שירותי פתיחה עשירים יותר (בטא).** צלמים, תקליטנים, ספקי אירועים ומקומות אירוח קטנים מתחילים עכשיו עם שניים-שלושה שירותים מוכנים (צילומי אירוע, הופעה באירוע פרטי, סיור והצעת מחיר, השכרת המקום לאירוע פרטי, טעימות ותכנון תפריט) במקום אחד.
- **אוכל ומסעדות: תתי-קטגוריות נוספות (בטא).** מסעדות, מאפיות וקייטרינג מצטרפים לפיצריות ובתי קפה, וכל אחד מתחיל עם שירותים משלו (שולחן שף, סדנת אפייה, פגישת טעימות, אירועים פרטיים). בתי קפה מתחילים עכשיו עם סדנת בריסטה ואירוע פרטי במקום רשימה ריקה.
- **הגדרות אישיות.** "הגדרות" בתפריט תמונת הפרופיל פותח את הדף האישי (מחוץ לאזור העסק): תמונה, שם, טלפון, תאריך לידה וכתובת מגורים (מיגרציה 0063), וחלק נגישות עם שפה וערכת נושא (הועברו מסרגל הכלים בדפים אחרי כניסה) וגם ניגודיות, גודל טקסט והפחתת תנועה, שנשמרים במכשיר.
- **תפקידים, הרשאות ומחיקת פריטים ([אפיון](proposals/roles-permissions-2026-10.md), X31).** דף התפקידים מציג את התפקידים המובנים ומה כל אחד יכול לעשות, לפני שיוצרים תפקיד משלך; בכל שורה בצוות יש חלון "הרשאות" עם מה שהאדם באמת יכול לעשות; בעלים ומנהלים (לא קבלה או עובדים) יכולים למחוק שירותים, מנויים וכרטיסיות, עם אישור, ופריט שיש לו שיעורים או מכירות מוסתר במקום להימחק כדי שההיסטוריה תישמר. ה-API אוכף (`catalog.delete`), ומי שאין לו הרשאה לא רואה את הכפתור.
- **הוספת סניף (X28).** בעלים מוסיפים סניף מטופס אחד: שם, כתובת, שעות פתיחה שמועתקות מסניף אחר, ומי מהצוות עובד שם. הטופס מציג בראשו את המחיר החודשי ומחייב אישור מצד הבעלים; עדיין לא מחייבים בפועל (ספקי התשלום לא מחוברים), והמודול "סניפים נוספים" פשוט עוקב אחרי הסניפים הפעילים.
- **לוח יומן רב-סניפי ([אפיון](proposals/schedule-board-2026-10.md)).** היומן מציג סניפים זה לצד זה מתחת לכל יום, עם כותרת סניף בצבע ובשם (יום עד 6 סניפים, שבוע עד 3, חודש 1), תצוגת חודש חדשה, פס משמרות מסומן לכל סניף (המספר הלא-מוסבר בצד מוסבר), חיצי יום/שבוע/חודש ברורים, בורר תאריך, וברירת מחדל לכל עסק שהבעלים שומר (מיגרציה 0060). הגריד הוא רכיב משותף (`components/calendar-board`) שלוח סידור העובדים משתמש בו.
- **חיתוך תמונות לפני שמירה (X27).** בחירת תמונת פרופיל או לוגו פותחת חלון: גוררים ומקרבים את התמונה בתוך עיגול (עכבר, גלגלת, מחוון או מקלדת) ושומרים את הריבוע שנראה. בנוסף פלטה רביעית, **הצבעים שלי**: בוחרים רקע, טקסט וצבע מבטא וכל המערכת מתעצבת לפיהם; כל שאר הגוונים מחושבים ומותאמים לניגודיות קריאה, כך ששום שילוב (הכול שחור, אותו צבע שלוש פעמים) לא שובר את המסך. מצב בהיר/כהה נקבע לפי הרקע.
- **שדרוג סביבת העבודה (רשימת 16 הסעיפים שלך, [תוכנית](proposals/crm-upgrade-2026-10.md), X23–X26).** פרופיל אישי עם תמונה, טלפון ותפריט משתמש; שלוש ערכות צבע (MyBiz שחור/לבן/סגול עמוק כברירת מחדל, אוקיינוס, יער) בבהיר ובכהה; סוג ישות ומספר רישום של העסק (עם ספרת ביקורת) ותמונת כיסוי; תרשים ארגוני עם תפקידים וקווי דיווח (לא משנה הרשאות); שעות פתיחה לכל סניף כולל הפסקות; לוח משמרות שבועי (מניעת חפיפות, אזהרות, העתקת שבוע) ודף שעות פשוט לעסק של אדם אחד; יומן יום/שבוע עם קו "עכשיו" חי, צבעי סניפים ומשמרות; השוואת סניפים בדוחות; חלון אחד למעבר בין עסק לסניף; מסכים משותפים מתרעננים בחזרה ללשונית וכל דקה. דמו: לכל הדמואים יש תפקידים, היררכיה, שעות ומשמרות, ודמו חדש `networks` יוצר לבעלים אחד את Urban Slice (פיצה, 4 סניפים), Pulse Fitness (2) ו-Studio Bloom (3), עם קטגוריה חדשה מסעדות ואוכל (בטא).
- **סידור עובדים לרשתות ([תוכנית](proposals/shift-scheduling-2026-10.md), X30).** לוח המשמרות נפתח לפי קצב הסידור של כל סניף (שבועי כברירת מחדל; יומי, חודשי או מותאם) ומציג יום, שבוע, חודש או טווח מותאם, לפי עובד או לפי סניף זה לצד זה (יום: הרבה סניפים, שבוע: עד 3, חודש: אחד). לכל עובד יש סניף בית, ומשמרת בסניף אחר מסומנת כהחלפה. בעל העסק יכול לשמור את התצוגה, הטווח והסניפים של לוח המשמרות כברירת מחדל לעסק (כמו ביומן). תכנון המוני: אפשר להעתיק יום ל-1/3/6 הימים הבאים, או שבוע ל-1/2/4 השבועות הבאים (התנגשויות מדולגות). בתצוגה לפי סניף אפשר ללחוץ על משמרת כדי לערוך אותה, ויש "+" להוספת משמרת לכל סניף ויום. הבא: כלי תכנון המוני ותצוגת תפקידים והרשאות (שרשור נפרד). חופשות מופיעות בלוח: תגית "בחופשה" ביום של העובד, וטופס המשמרת מזהיר כשהעובד שנבחר בחופשה (נקודת קצה חדשה `GET /shifts/time-off`). בטלפון לוח העובדים הופך לכרטיס לכל יום. תבניות משמרת: סניף שומר סוגי משמרת בשם ("בוקר 07:00-15:00") ומחיל אחד בלחיצה בטופס המשמרת. איוש מינימלי: הבעלים או מנהל קובע לכל סניף כמה אנשים נדרשים לפחות במשמרת לפי יום בשבוע וטווח שעות; הלוח מסמן קטעים חסרי איוש (באנר, סימון ביום ושורות בתצוגה לפי סניף; מי שבחופשה לא נספר). מיגרציה 0065.
- **משמרות: בקשות חופשה (פרוסה 1 של החלפות ובקשות).** עובד מבקש ימי חופש (`POST /time-off-requests`), רואה ומבטל את הבקשות שלו; מנהל רואה את התור עם מספר המשמרות שכבר יש לעובד באותם ימים, ומאשר או דוחה עם הערה. אישור מוסיף את שורת החופשה הרגילה, כך שהלוח וההזמנות מגיבים כמו קודם. מיגרציה 0072. באפליקציית העסק יש מסך "הסידור שלי" (בלשונית אני): המשמרות ב-4 השבועות הקרובים, הבקשות שלך עם הסטטוס (אפשר לבטל כל עוד ממתינה) וטופס לבקשת חופשה. תור בווב, החלפת משמרות וזמינות יגיעו בהמשך.
